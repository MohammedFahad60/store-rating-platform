# MySQL 8 Compatibility Audit

**Target production stack:** `mysql2` + Sequelize 6 + MySQL 8.
**Audit method:** static source inspection of the entire `Backend/` tree
(models, controllers, routes, middleware, config, migrations, seed, scripts),
plus full API execution on the test database (SQLite) exercising every query
path. Every finding below was checked against MySQL 8 semantics (InnoDB,
utf8mb4, MySQL 8.0 keywords/types).

> **Important:** a live MySQL 8 server could not be started in this sandbox
> (no MySQL/MariaDB binaries available, restricted environment). See the
> [Production Readiness Report](./PRODUCTION_READINESS_REPORT.md). This
> document is a careful static audit; no claim of live MySQL verification is
> made.

---

## 1. Dialect configuration

| Check | Result | Evidence |
|---|---|---|
| `dialect: "mysql"` for development/production | ✅ | `config/db.js` — `DB_DIALECT` defaults to `"mysql"`; MySQL branch explicitly passes `dialect: "mysql"` |
| `mysql2` driver | ✅ | `config/db.js` — `dialectModule: require("mysql2")` |
| `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD` | ✅ | All five read from env; `DB_PORT` numeric with 3306 default |
| SQLite never silently production | ✅ | SQLite only when `DB_DIALECT=sqlite` is explicitly set; production refuses to start with SQLite (`server.js`); `.env.example` marks SQLite as test-only |
| Charset/collation | ✅ | `define.charset: "utf8mb4"`, `define.collate: "utf8mb4_unicode_ci"` |
| fail-fast config errors | ✅ | Missing `DB_NAME`/`DB_USER` throw a clear config error; unsupported dialect throws |

## 2. Raw SQL / `Sequelize.literal`

All raw SQL lives in two controllers and the health check:

| Location | Query | MySQL 8 verdict |
|---|---|---|
| `storeController.getStores` | `(SELECT AVG(r.rating) FROM Ratings r WHERE r.storeId = Store.id)` (filter + attribute) | ✅ Valid MySQL; `Ratings`/`Stores` match Sequelize table names; `Store` is the Sequelize alias (not a MySQL reserved word) |
| `storeController.getStores` | `(SELECT COUNT(*) FROM Ratings ...)`, `(SELECT COUNT(*) FROM Services ... AND s.active = 1)` | ✅ `active = 1` is correct for `TINYINT(1)` |
| `storeController.getStores` | ORDER BY alias `averageRating` / `ratingCount` | ✅ MySQL allows ordering by select alias |
| `storeController.getStoreById` | `SELECT AVG(rating) AS avg ... WHERE storeId = ?` with `replacements` | ✅ Parameterized `?` is mysql2-native; `AVG` returns `DECIMAL` from MySQL (handled with `Number()`) |
| `storeController.getStoreById` | `SELECT COUNT(*) AS c FROM Services ...` | ✅ |
| `storeController.ownerDashboard` | `SELECT COALESCE(SUM(price), 0) AS revenue ...` | ✅ `COALESCE` + `SUM` valid; DECIMAL string converted with `Number()` |
| `storeController.ownerDashboard` | `SELECT AVG(rating) AS avg ...` | ✅ |
| `healthController` | `SELECT 1` | ✅ |

**SQL-injection status:** every raw query uses Sequelize `replacements`
(positional `?`), which mysql2 turns into bound parameters. Literal fragments
contain only fixed identifiers - never user input. The `minRating` filter is
validated to `1..5` before use.

## 3. Sequelize operator usage

| Construct | Location | MySQL 8 verdict |
|---|---|---|
| `Op.like` (search) | `storeController.getStores` | ✅ `%...%` LIKE, parameterized |
| `Op.and` / `Op.or` / `Op.in` / `Op.ne` | stores, bookings, dashboards | ✅ |
| `ORDER BY`, `LIMIT`, `OFFSET` | discovery (limit/offset), recent lists (limit) | ✅ generated by Sequelize dialect layer; `LIMIT/OFFSET` syntax identical |
| `COUNT` | admin/owner dashboards (`Model.count`) | ✅ |
| `AVG` | only inside raw SQL above | ✅ |
| `GROUP BY` | not used (aggregates are subqueries) | ✅ no `ONLY_FULL_GROUP_BY` hazard |
| `DATE` functions | none used; `bookingDate` is a `DATEONLY` comparison by Sequelize | ✅ `DATEONLY` maps to MySQL `DATE` |
| `sequelize.where(literal, ">=", value)` | `minRating` filter | ✅ |

## 4. Column types

| Sequelize type | Model / migration | MySQL 8 type | Verdict |
|---|---|---|---|
| `INTEGER` | ids, FKs, rating, estimatedMinutes, tokenVersion | `INT` | ✅ |
| `ENUM(...)` | `Users.role`, `Stores.status`, `Bookings.status` | native `ENUM` | ✅ (created by migrations, not just sync) |
| `BOOLEAN` | `Services.active` | `TINYINT(1)` | ✅ raw `active = 1` matches |
| `DECIMAL(10,2)` | `price` | `DECIMAL(10,2)` | ✅ |
| `DECIMAL(10,8)/(11,8)` | lat/long | ✅ |
| `STRING(n)` | names, email, phone, notes | `VARCHAR(n)` with utf8mb4 | ✅ `email` unique = 255×4 = 1020 bytes < 3072-byte InnoDB limit |
| `TEXT` | descriptions, comments | `TEXT` | ✅ |
| `DATEONLY` | `bookingDate` | `DATE` | ✅ |
| `TIME` | opening/closing | `TIME` | ✅ |
| `JSON` | **not used anywhere** | n/a | ✅ no JSON pitfalls |
| `TIMESTAMPS` | createdAt/updatedAt | `DATETIME NOT NULL` | ✅ created by migrations with `CURRENT_TIMESTAMP` default |

| Check | Result | Evidence |
|---|---|---|
| Primary keys | ✅ | `id` auto-increment PK on all 5 tables (migrations 0001–0005) |
| Foreign keys | ✅ | Store.ownerId→Users, Service.storeId→Stores, Booking.userId/storeId/serviceId, Rating.userId/storeId/bookingId (CASCADE / SET NULL) |

## 6. SQLite-specific SQL

None in application code. SQLite appears only in `config/db.js` (test
dialect branch) and `scripts/e2e-verify.js` (test harness env). All queries
run identically against SQLite (verified by the 87-check E2E suite) and are
MySQL-valid.

## 7. Determinism / reproducibility from an empty MySQL database

1. `CREATE DATABASE store_rating_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
2. `npm run db:migrate` → migrations 0001–0005 create all tables, FKs,
   indexes and unique constraints.
3. `npm run seed` → deterministic demo data (bcrypt-hashed passwords,
   fixed users/stores/services/bookings/ratings, single transaction).
4. Re-running `db:migrate` is a no-op; re-running `seed` rebuilds the same
   dataset.

## 8. Remaining risks / notes

- `MIN`/`MAX` etc. aggregates used only inside literal subqueries - safe.
- MySQL aliases that could collide with reserved words were checked:
  `Store`, `Ratings`, `Services`, `Bookings`, `Users` are not MySQL 8.0
  reserved words.
- DECIMAL values arrive as strings from mysql2; all API responses convert
  prices/ratings with `Number()` before returning (or return the Sequelize
  value, which the React frontend also parses with `Number()`).
- No `JSON` columns, so no MySQL 8 `JSON`/`JSON_TABLE` compatibility work is
  required.
